# Blackwire v0.4 — Security Hardening Update

This release addresses 28 security findings identified during a comprehensive audit
of the server (Python/FastAPI), client (C++/Qt), and infrastructure (Docker) layers.

---

## Summary

| Severity | Count | Fixed | Deferred to v0.5 |
|----------|-------|-------|-------------------|
| Critical | 5     | 5     | 0                 |
| High     | 5     | 5     | 0                 |
| Medium   | 9     | 9     | 0                 |
| Low      | 9     | 7     | 2                 |
| **Total**| **28**| **26**| **2**             |

## Critical

### 1. Default JWT Secret Accepted in Production
**Component:** Server · `config.py`, `main.py`  
**Risk:** The default `jwt_secret_key` value (`change-this-secret-minimum-32-bytes`)
passed the length check, allowing production deployments with a well-known secret.  
**Fix:** Startup now checks the secret against a blocklist of known insecure defaults.
Non-dev environments raise a `RuntimeError`; dev environments log a warning.

### 2. Federation Byte Rate-Limit Key Spoofable
**Component:** Server · `api_v2/federation.py`  
**Risk:** The byte-rate-limit key was derived from the unauthenticated `x-bw-sender`
header. An attacker could rotate this header to bypass the rate limit entirely.  
**Fix:** The key is now derived from `X-BW-Fed-Server`, which is cryptographically
verified by `federation_security_service.verify_incoming()` before the rate check runs.

### 3. No TLS Certificate Validation on Client HTTP Requests
**Component:** Client · `qt_api_client.cpp`  
**Risk:** `QNetworkAccessManager` used default SSL config with no explicit peer
verification. On some platforms/Qt builds, this could silently accept invalid certs.  
**Fix:** Non-`.onion` HTTPS requests now explicitly set `QSslConfiguration` with
`VerifyPeer` mode enabled.

### 4. Default Base URL Uses Plaintext HTTP
**Component:** Client · `state_store.cpp`, `application_controller.cpp`  
**Risk:** New installations defaulted to `http://localhost:8000`, meaning any
mis-configured remote connection would transmit credentials in plaintext.  
**Fix:** Default base URL changed to `https://localhost:8000`. The `--base-url`
CLI flag for smoke mode retains `http://` for local dev convenience.

### 5. Private Key Material Not Zeroed After Use
**Component:** Client · `sodium_crypto_service.cpp`  
**Risk:** Stack buffers and decoded `std::vector<unsigned char>` holding Ed25519
and X25519 private keys were never scrubbed, leaving key material recoverable from
process memory or swap.  
**Fix:** All private key buffers are now wiped with `sodium_memzero()` on every code
path (including error paths) in `GenerateDeviceKeys()`, `DecryptWithPrivate()`, and
`SignDetached()`.

## High

### 6. V1 WebSocket Skips DB User Validation
**Component:** Server · `main.py`  
**Risk:** The V1 `/api/v1/ws` endpoint decoded the JWT but never checked whether the
user still existed or had been disabled in the database, allowing revoked users to
maintain an active WebSocket.  
**Fix:** A database lookup (`User.id == sub AND disabled_at IS NULL`) now runs before
accepting the WebSocket connection.

### 7. Login Password Field Has No Maximum Length
**Component:** Server · `schemas/auth.py`, `schemas/v2_auth.py`  
**Risk:** `LoginRequest` and `LoginRequestV2` accepted arbitrarily long passwords.
An attacker could submit multi-megabyte passwords, causing Argon2 to consume excessive
CPU and memory (hash-based DoS).  
**Fix:** Both schemas now enforce `max_length=128` (matching `RegisterRequest`).

### 8. WebSocket Reconnect Reuses Stale Token
**Component:** Client · `qt_ws_client.cpp`, `qt_ws_client.hpp`, `ws_client.hpp`  
**Risk:** On automatic reconnect, the WS client reused the same access token stored at
initial connection time. If the token had expired the reconnect would fail silently.  
**Fix:** Added `SetTokenRefreshCallback` to `IWsClient`. When set, the reconnect timer
invokes the callback to obtain a fresh access token before opening the socket.
`ApplicationController::StartRealtime()` now wires a callback that calls
`RefreshAccessToken()` + `RequireAccessToken()`.

### 9. Social Graph Metadata Stored Unencrypted
**Component:** Client · `client_state.hpp`  
**Risk:** Friend-list and group membership metadata in `client_state.json` is stored as
plaintext, exposing the social graph if the file is exfiltrated.  
**Status:** Deferred to v0.5 — requires architectural redesign of state file format to
apply sealed-box encryption to social fields at rest with a user-derived key.

### 10. State File Written with Default Permissions
**Component:** Client · `state_store.cpp`  
**Risk:** `std::ofstream` inherits parent directory permissions, potentially making
`client_state.json` world-readable on shared systems.  
**Fix:** After writing, the file is restricted with `_chmod(path, _S_IREAD | _S_IWRITE)`
on Windows. POSIX platforms already benefit from `umask`.

## Medium

### 11. WebSocket Token Accepted via Query Parameter
**Component:** Server · `main.py`  
**Risk:** The `_extract_bearer_token()` helper fell back to `?access_token=` in the URL.
Tokens in query strings leak via server logs, proxy logs, and Referer headers.  
**Fix:** The query-parameter fallback has been removed. WebSocket tokens must be sent via
the `Authorization: Bearer …` header.

### 12. In-Memory Rate Limiter Not Flagged in Production
**Component:** Server · `services/rate_limit.py`  
**Risk:** Without Redis, rate limits operate per-process and are reset on restart. A
multi-worker deployment could have effectively no rate limiting.  
**Fix:** A warning is now logged at startup when the in-memory limiter is active outside
dev mode, advising operators to enable Redis.

### 13. Federation Client Uses Plaintext HTTP for All Peers
**Component:** Server · `services/federation_client.py`  
**Risk:** All outbound federation HTTP requests used `http://`, including requests to
clearnet (non-`.onion`) peers, exposing payloads to network observers.  
**Fix:** A new `_build_base_url()` helper returns `http://` only for `.onion` hosts
(which are already end-to-end encrypted by Tor) and `https://` for all others.

### 14. No Per-Account Brute-Force Rate Limiting
**Component:** Server · `api/auth.py`, `api_v2/auth.py`, `api/utils.py`  
**Risk:** Login rate limiting was IP-only. An attacker with multiple IPs could attempt
unlimited password guesses against a single username.  
**Fix:** Added `user_rate_limit_key()` helper. Login endpoints now enforce a secondary
per-username limit of 10 attempts per minute in addition to the existing per-IP limit.

### 15. V1 API Uses HS256 Symmetric JWT
**Component:** Server · `security/tokens.py`, `main.py`  
**Risk:** HS256 means any service that can verify tokens can also forge them. In a
multi-service architecture this is a privilege-escalation vector.  
**Fix:** A deprecation warning is logged at startup when V1 routes use HS256, recommending
migration to V2 (EdDSA). Full removal is planned for v0.5.

### 16. Signed Prekey Signature Not Verified Before Use
**Component:** Client · `application_controller.cpp`  
**Risk:** Resolved prekeys were accepted from the server without verifying the Ed25519
signature, allowing a compromised server to inject rogue prekeys.  
**Fix:** After resolving prekeys, the client now reconstructs the canonical signed-prekey
string and calls `VerifyDetached()` against the device's public signing key. Prekeys with
invalid signatures are skipped with a diagnostic log entry.

### 17. Chain Hash Mismatch Only Warns — Does Not Reject
**Component:** Client · `application_controller.cpp`  
**Risk:** When a sender's `prev_hash` didn't match the last verified chain hash, the
message was still displayed. This rendered the chain-hash integrity check advisory-only.  
**Fix:** When the expected previous hash is known (i.e. not the first message from that
sender-device), a mismatch now causes the message to be rejected (`return`). The first
message from an unknown sender-device is still accepted to handle fresh conversations.

### 18. Video Temp Files Not Cleaned Up on Crash
**Component:** Client · `chat_widget.cpp`  
**Risk:** Decrypted video temp files (`blackwire_video_*`) survived process crashes because
`setAutoRemove(false)` was used and cleanup only happened on dialog close.  
**Fix:** Before creating a new temp file, the play handler now scans `QDir::tempPath()` for
orphaned `blackwire_video_*` files and removes them, ensuring no stale decrypted media
persists across sessions.

## Low

### 19. Docker Compose Hardcodes Database Credentials
**Component:** Infra · `docker-compose.yml`  
**Risk:** `POSTGRES_PASSWORD: blackwire` was committed to version control.  
**Fix:** Replaced all hardcoded values with `${VAR:-default}` env-var references.
`POSTGRES_PASSWORD` now uses `${POSTGRES_PASSWORD:?Set POSTGRES_PASSWORD in .env}` which
makes Docker Compose fail immediately if the variable is unset.

### 20. Metrics Endpoint Exposes All Counters to Any User
**Component:** Server · `api/metrics.py`  
**Risk:** Any authenticated V1 user could read internal counters (auth failures, message
rates, etc.), leaking operational data.  
**Fix:** The endpoint now returns `403 Forbidden` in production environments.

### 21. Health Endpoint Leaks Migration Version
**Component:** Server · `api/health.py`  
**Risk:** The `migration_version` field revealed the exact database schema version,
helping attackers fingerprint the deployment.  
**Fix:** `migration_version` removed from the `/health/ready` response payload. The
readiness check still validates that a migration version exists internally.

### 22. Registration Endpoint Reveals Existing Usernames
**Component:** Server · `services/auth_service.py`  
**Risk:** Registration returned `409 "Username already exists"`, allowing enumeration.  
**Fix:** Error message changed to a generic `"Registration failed"`. The 409 status code
is retained for client compatibility, but the detail no longer confirms existence.

### 23. No Password Complexity Requirements
**Component:** Server · `services/auth_service.py`  
**Risk:** Only `min_length=8` was enforced. Users could choose trivially guessable
passwords like `aaaaaaaa`.  
**Fix:** `_validate_password_complexity()` now requires at least one uppercase letter,
one lowercase letter, one digit, and one special character.

### 24. Federation Device Enumeration
**Component:** Server · `api_v2/federation.py`  
**Risk:** Federation endpoints expose device lists to authenticated peer servers.  
**Status:** Accepted risk — device enumeration is inherent to the federated key-exchange
model. Federation endpoints are already gated behind cryptographic server-identity
verification (Ed25519 signed requests).

### 25. `retry_payload` Stored as Plaintext in State
**Component:** Client · `application_controller.cpp`  
**Risk:** Failed outbound messages stored in `retry_payload` within `client_state.json`
contain plaintext message content.  
**Status:** Deferred to v0.5 — the retry mechanism needs rework to store only the
encrypted envelope and re-encrypt on retry.

### 26. Attachment Metadata Not Stripped
**Component:** Client · `chat_widget.cpp`  
**Risk:** The suggested filename in the save dialog comes from the sender and may contain
relative path traversal sequences. Additionally, saved images/videos may retain EXIF or
other metadata.  
**Status:** Deferred to v0.5 — requires platform-specific metadata-stripping libraries.
Path traversal is partially mitigated by `QFileDialog` presenting the filename as a
suggestion that the user must confirm.

### 27. Credential Deletion Uses Substring Match
**Component:** Client · `windows_credential_store.cpp`  
**Risk:** `DeleteSecretsMatching()` used case-insensitive substring search across all
system credentials. A Blackwire credential name that happened to be a substring of an
unrelated credential could cause accidental deletion.  
**Fix:** Changed from `.find()` (substring) to `.rfind(needle, 0)` (prefix match), so
only credentials whose names start with the given needle are deleted.

### 28. WebSocket Reconnect Backoff Has No Jitter
**Component:** Client · `qt_ws_client.cpp`  
**Risk:** Deterministic exponential backoff causes all disconnected clients to reconnect
at the same instant (thundering herd), potentially overwhelming the server.  
**Fix:** `ScheduleReconnect()` now adds random jitter of 0–25% of the base delay.

## New Feature: Self-Signed TLS & Client Certificate Warning

### Server: Auto-Generated Self-Signed TLS Certificate
**Component:** Server · `Dockerfile`, `entrypoint.sh`, `config.py`

The server now auto-generates a self-signed TLS certificate on first start when
`BLACKWIRE_TLS_ENABLED=true` (the default). This means the server immediately
serves HTTPS without requiring an external CA or manual certificate setup.

**How it works:**
- On container start, `entrypoint.sh` checks whether certificate files exist at
  the paths given by `BLACKWIRE_TLS_CERT_FILE` / `BLACKWIRE_TLS_KEY_FILE`.
- If they are missing, it generates a self-signed RSA-2048 certificate valid for
  365 days with SAN entries for `localhost` and `127.0.0.1`.
- Uvicorn is started with `--ssl-keyfile` / `--ssl-certfile` to serve HTTPS.
- Certificates are persisted in a Docker volume (`blackwire_certs`) so they
  survive container restarts.
- Set `BLACKWIRE_TLS_ENABLED=false` to disable TLS and serve plain HTTP.

**New environment variables:**
| Variable | Default | Description |
|---|---|---|
| `BLACKWIRE_TLS_ENABLED` | `true` | Enable/disable TLS |
| `BLACKWIRE_TLS_CERT_FILE` | `/app/certs/server.crt` | Path to TLS certificate |
| `BLACKWIRE_TLS_KEY_FILE` | `/app/certs/server.key` | Path to TLS private key |

### Client: SSL Certificate Warning Dialog
**Component:** Client · `qt_api_client.cpp`, `qt_ws_client.cpp`, `ssl_trust.hpp`

When connecting to a server that presents a self-signed or otherwise untrusted
TLS certificate, the client now shows a warning dialog with certificate details
(subject, issuer, SHA-256 fingerprint) and asks the user whether to proceed.

- If the user clicks **Yes**, the certificate fingerprint is remembered for the
  duration of the session so subsequent HTTP and WebSocket connections are not
  prompted again.
- If the user clicks **No**, the connection fails with an SSL error.
- The shared `SslTrust` class in `ssl_trust.hpp` handles both `QNetworkReply`
  (HTTP) and `QWebSocket` SSL errors with a common fingerprint store.

## Upgrade Notes

1. **BLACKWIRE_JWT_SECRET_KEY** — Generate a new unique secret if running outside `dev`.
   The known default is now rejected in `test` and `prod` environments.
2. **POSTGRES_PASSWORD** — Set `POSTGRES_PASSWORD` in your `.env` file before running
   `docker compose up`. The hardcoded default has been removed.
3. **WebSocket clients** — The `?access_token=` query parameter is no longer accepted.
   Clients must send the token via the `Authorization` header (already the default in
   the C++ client).
4. **Password policy** — Existing users are unaffected, but new registrations and password
   changes now require mixed-case, digit, and special character.
5. **Default base URL** — New client installations default to `https://localhost:8000`.
   Existing state files retain whatever URL was previously saved.
6. **TLS is now on by default** — The server serves HTTPS with a self-signed cert.
   Clients connecting via `https://` will see a certificate warning on first
   connection. Set `BLACKWIRE_TLS_ENABLED=false` to revert to plain HTTP.
